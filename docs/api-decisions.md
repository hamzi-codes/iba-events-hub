## C. # API Decisions (where the contract was silent)

| #   | Topic                                    | What the code does                                                                                                                                                                                                                                                  |
| --- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `GET /organisations?category=`           | `category` is required (400 if missing or wrong).                                                                                                                                                                                                                   |
| 2   | `GET /organisations/:id/events`          | The contract says "events the caller may see (5.8)", so: students see only Approved plus cancelled-after-approval; an organiser/approver also sees every status for their own organisations; admin sees all. The org page therefore shows a status for those roles. |
| 3   | `GET /settings/event-types`              | Returns a plain array of names, e.g. `["Workshop","Other"]`. Umer must read it that way.                                                                                                                                                                            |
| 4   | `upcomingCount` in the organisation list | Counts what any student can see (approved or cancelled-after-approval) that has not ended.                                                                                                                                                                          |
| 5   | `GET /approvals/decided`                 | Returns a plain array, one row per decision, newest first. Each row is the event plus `decision: { status, comment, decidedAt, decidedBy }`. Date-only `from`/`to` mean that day in Pakistan time.                                                                  |
| 6   | Approve error order                      | 404, then 403 (not your organisation), then 403 SELF_APPROVAL_NOT_ALLOWED, then 400 (comment), then 409 ALREADY_DECIDED (a Cancelled event gives INVALID_STATUS), then 400 EVENT_ALREADY_STARTED, then 409 VENUE_CONFLICT.                                          |
| 7   | Venue clash on approve                   | A copy of the 5.10 query lives in `approvalsController.js` with a TODO. Swap to Ali's `services/conflict.js` when it exists.                                                                                                                                        |
| 8   | Queue order                              | Oldest by `updatedAt`, so a resubmitted event goes to the back of the queue.                                                                                                                                                                                        |
| 9   | Admin user object                        | The contract user object plus `isActive`, `isVerified`, `createdAt` (screen 22 needs `isActive`).                                                                                                                                                                   |
| 10  | `GET /admin/organisations`               | Active and inactive in one list by default (`includeInactive=false` hides inactive ones). Each org includes `approvers` and `organisers` arrays `[{id, fullName, email}]` plus counts, for screens 23 and 24.                                                       |
| 11  | Roles                                    | Roles follow links: organiser/approver exist only while the user has a link of that type; everyone keeps `student`. An admin can grant `admin`, but cannot remove their own admin role or deactivate themselves.                                                    |
| 12  | Settings                                 | `PUT /admin/settings` trims, lower-cases domains, removes duplicates, and refuses empty lists (an empty domain list would block all sign-ups).                                                                                                                      |
